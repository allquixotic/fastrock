## §I INTERFACES
- I.shell: horizontal document tabs for chats, Rally, files and Settings; chat-only project-grouped sidebar; optional information panel; active/busy/error marks; close/middle-close, reorder, overflow scrolling, contextual actions and pop-out native windows. Preserve drafts, scroll/selection, active turns and document identity across moves; no duplicate submissions.
- I.interactions: audit every Slint callback/menu action/key binding. Include global menus; configurable shortcuts; native text selection/copy/paste; transcript copy/link/file/diff actions and find; sidebar search/folder/thread menus; new-folder/recent-folder flows; composer attachments/pickers/suggestions/slash actions/queue/steer/stop; approvals; info tools/usage/goals/terminals/agents; supported Settings actions. Explicit original-user exclusions (embedded server/Rust build) override reference features.
- I.codex: newline JSON-RPC subprocess, correlated/cancellable requests, notification streaming, human approvals/questions, thread start/list/read/resume/fork/archive/delete/name, turns, queues, skills/MCP/config/account. Preserve per-thread isolation and Codex ownership of transcript history.
- I.windows: pop-out in tab right-click menu; independent native OS windows using same application state/services. Window close must not lose unsaved work or interrupt unrelated windows. Return/move documents between windows, synchronize shared settings, clean orphan processes, retain app-server until last dependent window closes.
- I.rally: configurable endpoint/API token in Settings; direct WSAPI v2; workspace/project parent/child scope, iteration/release, fields/schema, custom fields, CRUD, discussions/tasks/children/attachments/revisions, saved private views, CSV export. HTTPS except loopback tests; OS keyring secrets; origin/redirect containment.
- I.board: responsive state lanes/cards with owners, estimates, task counts and blocked/ready; drag state transition; rich detail editing/display; local/server filtering, sorting/grouping and search. No user-facing story-count/page-size controls. Load relevant pages incrementally, cache bounded projections, virtualize offscreen cards/rows, load ahead near viewport, cancel obsolete scopes, deduplicate calls and refresh visibly on demand.
- I.refresh: Refresh always reachable in Rally, including detail/error/loading views. Stale-while-refresh; active-view freshness checks with backoff/jitter; inactive views pause. Manual refresh re-queries; no request per frame/keystroke; edits invalidate relevant cache. Protect unsaved details.
- I.ai: prompt from Rally; typed query/view/proposal tools, context scoped to current work; explain/filter/group actions; explicit preview/apply for mutations; reread revisions, stop on first conflict/failure, report partial results. Untrusted Rally text is data; never include tokens in prompts.
- I.rich: native formatted Unicode text, selection/caret, bold/italic/underline/strike, lists/headings/quotes/code/links, preview, raw HTML and undo/redo; descriptions/notes/acceptance/custom HTML/comments. Preserve unchanged HTML exactly; disclose unsupported rich structures and retain source editing.
- I.persistence: preferences, window/tab organization, drafts/attachments/queues and private views; atomic bounded background writes. Codex retains history. Never auto-submit restored queued work. Credentials only OS keyring or injected test environment.
- I.performance: aggregate Fastrock UI/service processes (exclude Codex) target few hundred MiB under heavy ordinary use; 384 MiB aggregate RSS pressure threshold, 480 MiB fixture assertion ceiling; 256 MiB Go soft heap budget divided across windows. Track process resident + Go memory, bound caches and queues, evict inactive/reconstructible data, shed old transcript/render pages, release GPU surfaces, back off fetching. Never purge unsaved edits or active approvals. Budget is target, not promise for arbitrary user-owned data/window counts.
- I.operations: builds/doctor/version, actionable errors, Windows native dialogs/clipboard, macOS system integrations, no production telemetry requirement. Browser links external only; files/diffs native.
- I.navigation-polish: expanding/collapsing large conversation folders and showing/hiding the sidebar must feel immediate. Render only visible rows; invalidate grouping on metadata changes, never hash the entire history per frame. Use drawn disclosure chevrons and an identifiable information-panel icon with tooltips. Size Settings to its label plus modest padding. Status/footer hidden by default; close with X and restore through View. Rally primary navigation uses broad Home/Plan/Track/Quality/Portfolio/Reports sections with clear selected-state styling and subordinate page navigation, matching the user's attached reference.
- I.updates: release builds automatically check GitHub Releases and download compatible updates in the background; Help offers a manual check. Verify SHA-256 before extraction; authenticate native publisher and signed version before ready and install. Require Windows Authenticode or macOS Developer ID/notarization. Bound downloads/extraction and reject unsafe archive paths. Stage without interrupting work, then install when all windows exit. A separate copy of the executable waits for shutdown, replaces locked Windows binaries or the macOS app bundle with rollback, and restarts. Errors remain recoverable and visible; no administrative elevation, installer wizard, separate runtime, or private update infrastructure. Development builds do not auto-install themselves.
- I.distribution: Windows releases establish a per-user installation and Start menu shortcut automatically on launch. Never require administrator access. macOS ships an app bundle in a DMG with an Applications link; support user-owned ~/Applications when /Applications is not writable. Updates preserve preferences, credentials, drafts and window state. Release automation publishes versioned platform archives, DMGs and checksums.
