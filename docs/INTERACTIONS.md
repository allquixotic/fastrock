# Codex GUI interaction audit

Reference: the Slint/Rust `codex-rs/gui/ui` and `codex-rs/gui/src` tree in the
adjacent Codex checkout, reviewed 2026-10-09. The inventory includes the public
callbacks in app, composer, sidebar, newtab, approvals, transcript, files_state,
info, settings_state, settings_keyboard, settings_sandbox, bedrock and xtab.
Repeated callbacks in shared widget components map to their owning action.

An entry in the implementation column means an action reaches native state, the installed Codex protocol,
or the relevant OS operation. It does not mean every source widget has identical
geometry or that every server-dependent action was exercised against real accounts.

## Validation boundary

Earlier Windows fixture tests exercised chat/Rally streaming, filters, rich edits,
tab lifecycle, keyboard/native dialog flows and a large-board restart/pop-out scenario.
They predate this review patch. This patch adds headless regression coverage for
protocol/cache/persistence, draft preservation, paging and configuration behavior;
it has not rerun native Windows interaction or latency fixtures.
macOS is cross-built and tested headlessly only. Account/provider writes requiring
real credentials, production Rally writes and paid inference are not test fixtures.
The remaining differences above are tracked work, not completed parity claims.
Desktop notification delivery and the reference renderer-choice UI are not ported;
Fastrock uses its single pure-Go rendering backend. System theme following and
persistent dark/light overrides are implemented. Mixed-DPI and screen-reader acceptance are unverified.


## Item-by-item review status

[REVIEW-ASSESSMENT.md](REVIEW-ASSESSMENT.md) accounts for all 540 original findings,
including explicit disagreement reasons, applied fixes and accepted work that is
still partial or open. Neither RPC reachability nor passing headless tests imply
visual or end-to-end parity. The local SPEC task flags remain open accordingly.

Structured review targets offer uncommitted changes, a base branch, a commit or custom instructions. Inter-chat reply timeouts and transfer watchdogs use timers, leaving read workers available during long waits.

Clipboard paste stays attached to its original editor and selection. Delayed results are canceled with a notice if the editor changes or disappears; native clipboard errors are visible. Headless tests exercise these cases without OS clipboard access.

Structured unified diffs now show line-number gutters, change markers, file status/counts, summary totals, semantic backgrounds and intraline emphasis. Quoted paths, renames/copies, deletions, binary patches and bounded-output notices are explicit. File/hunk navigation expands hidden targets; source selection, collapse and scroll survive a window transfer. A single UTF-8 source and virtual line rows replace all per-file editor buffers. General file viewing still uses native text editors.

Pop-out timeouts and process failures resolve the broker outcome before cleanup. Confirmed cancellation keeps the source and terminates its child; a completed transfer keeps the destination. An uncertain outcome or broker loss keeps installed documents available. Empty abandoned pop-out windows close automatically.

Closing a pop-out returns documents to the main window, or another live window if the main one has closed. The pop-out closes after all transfers commit. Cancellation or a conflicting destination draft leaves it open. When it is the last window, documents use local session recovery.

Typography now uses real bold/italic faces, a shared caption/large/title scale, and monospace code/command/file views. Transcript and rich-editor selection/caret geometry follows the same fonts as drawing. Font changes update these roles; native mixed-DPI acceptance remains open.

Open disk files now show change/deletion notices while retaining the last loaded text through eviction and failed reloads. Paging refuses to mix file versions. Non-UTF-8 errors offer an explicit lossy text view with a replacement-character notice. Save as suggests a safe Markdown/text name, applies native text filters, commits atomically, and confirms success. Native dialog behavior has source/cross-build coverage; no dialog was opened on the Mac.

Settings starts on Common with grouped navigation and platform-specific Sandbox visibility. Persistent server/restart notices provide recovery actions. Account has typed summary/usage cards and organization-gated sign-in; policy loads independently from the model catalog. Common choices honor managed allowed-value lists. Settings rows retain pending/success/error feedback, with errors in red. Live quota updates merge over pending reads without erasing unavailable metadata.

MCP settings now merge all bounded status pages with configuration origins, show live connection status and expose removal only for user entries. Arguments, environment variables and HTTP headers have structured editors. Features group by stage and mark changes from defaults. Plugins group by marketplace; skills group by scope; hook rows show commands and trust status. Load errors and effective-value overrides stay visible.

All settings has separate search, inline source/help/lock reasons, grouped fields, and an open/recent-folder context chooser. Table values use scoped TOML snippets and notification commands use platform-specific quoting. Protected placeholders remain read-only. Settings form validation and save failures stay beside their controls; stale replies after reconnect cannot overwrite a newer attempt.

The info panel now uses shared collapsible sections, effective model/provider/permission summaries, structured agent rows and peer-linked mail. Process events refresh initially empty terminal lists; Stop all confirms the command list and calls the server clean operation. Closed/reconnected views discard late results. Disabling agent messages declines pending consent in every connected window.

Local providers displays independent Ollama and LM Studio cards, running state, installed-model rows and current-model state. Ollama model selection requires verified 0.13.4 or newer. Downloads show aggregate layer progress and contextual cancellation, with inline failures and stale-result guards. These paths use local HTTP/RPC fixtures; native visual acceptance remains open.

Cross-tab inputs carry an XML-escaped sender ID/title, reply expectation and unique delivery marker. Transcript cards and exports show the readable agent message; retained server history stays intact. Malformed or mixed-content envelopes remain visible as normal input.

MCP form requests now distinguish real forms, tool-call confirmations and install/enable suggestions. Tool cards name the server/tool and show at most six parameters. Session/always choices appear only when advertised by the server. Escape and closing the owning conversation send cancel. Suggestion links must be HTTP(S). Install/enable open-and-continue choices open the link after the selected answer is delivered. Ordinary URL authorization keeps separate Open and Submit actions.

Question cards show separate headers and wrapped prompts, contextual answer/note placeholders, Submit/Skip and unanswered guidance. MCP forms show per-field red validation, typed bounds and a form-level summary; invalid drafts remain editable and send no response. Boolean fields have a single required-marked header. Badges count requests for the current conversation, including routed sub-agent requests.

Recap summarizes up to eight recent exchanges and a pending correction in a temporary read-only thread with tools, MCP servers, skills and environments disabled. It posts a local Conversation recap card without adding a prompt or turn to the source thread. Cancel recap, tab close/transfer, server loss and timeouts release the temporary work; late start replies are also cleaned up.

Approval cards reserve their measured height alongside the composer, with wrapped titles/details and a scrollable body. Literal command text is selectable and copyable; file patches update while approval is pending, use colored counted hunks and stop at 400 preview lines. Missing patches are fetched asynchronously with request/server guards. Decision labels expose the actual saved prefix or host scope; an explicitly empty decision list never invents an approval action. Headless card and full-chat checks cover 100%, 150% and 200% scale. Very short windows can scroll the entire card.

Tab dragging now highlights the dragged tab and shows a two-pixel insertion marker. Pointer-derived slots account for rendered stride and horizontal scrolling; outside releases cancel and close buttons do not arm drags. Headless pointer fixtures cover the interaction; native mixed-DPI acceptance remains open.

Rally ranking uses [Broadcom’s documented rankAbove/rankBelow parameters](https://knowledge.broadcom.com/external/article/57511/how-to-rank-artifacts-using-web-services.html). The stored [DragAndDropRank value is opaque; Rank is not a WSAPI v2 property](https://knowledge.broadcom.com/external/article/57572/rally-get-numeric-rank-values-in-apps-a.html). Fastrock sends field and rank changes together, checking the prior revision before the write; this preflight is not a server-side atomic compare-and-swap.

Rally mode buttons follow the page: boards offer List/Board/Charts, timeboxes offer List/Charts, and planning/timeline pages keep a way back to their original mode. Grouping uses schema display names and preserves saved custom fields. Table group counts explicitly cover loaded matching records; server-wide group totals are not implied. Active filters remain visible as individually removable, wrapping chips when the filter editor is closed. Successful refreshes rebuild filtered records and counts while retaining worker-prepared search text.

Work-item collection tabs follow the artifact schema and show available counts. Tasks omit Tasks/Children, Feature children use UserStories, and Epic children use Children. Switching tabs hides the previous collection while loading; failed requests retain its cached page without displaying it under another heading. Discussions show initials, author/date, formatted read-only content and confirmed deletion. Revision History is a Revision/Date/User/Changes table. Content-sized rows use bounded background layouts and viewport drawing; longer posts offer their full source. Comment deletion preserves the composer draft and reports server failures.

Conversation tabs, their scrollable overflow list and sidebar rows share status colors and an open-idle ring. Sidebar rows retain full named titles for tooltips and show compact relative timestamps. New-tab actions reuse a start page; a newly requested page appears next to the active document, and a successful conversation start replaces only that page while preserving any newer selection.

The sidebar history menu exposes Open, new conversation in this folder, Rename, Archive/Unarchive, Delete and Copy thread ID. View as text reads chronological server history even for an unopened conversation; its preview is explicitly capped at 4 MiB, while full Markdown export retains the 64 MiB limit. Closing a loading text view cancels its request. Rally Refresh/Ask AI controls show a disabled state when unavailable, and 401/403 errors offer a direct path to Rally credential settings.

Queue movement and attachment buttons now explain their actions on hover. Folder and information section disclosures use drawn chevrons with Expand/Collapse tooltips; rich formatting and tab controls keep their existing tooltips.

Backlog lists stories with no Iteration. My Work waits for the authenticated Rally user and filters Owner by that verified reference; identity failures offer Retry. The lookup uses [Broadcom's documented unscoped user endpoint](https://knowledge.broadcom.com/external/article/74918), separately from the workspace user picker. New work items inherit that user, the selected project/timebox and originating lane state. A delayed identity can fill an untouched owner field, including after restoring or transferring its draft, but never replaces an explicit choice or clear.

Iteration Status starts on the iteration whose dates contain the current time, preferring the selected project if multiple iterations overlap. It shows summary metrics for the loaded matching records. No matching iteration is an explicit empty state. “Current iteration” remains relative in saved views and transferred tabs; switching to another timebox or removing its chip disables the automatic choice. Crossing an iteration boundary restarts paging. Scope changes cancel earlier requests before awaiting new metadata.

List ID and name cells are wrapping links. Row heights follow the complete measured text at the active display scale, and clicking a wrapped line opens its work item. Layout caches contain only the current table page and are discarded on eviction.


Work-item details use a 72/28 content/properties split when space allows, with a sidebar at least 300 logical pixels wide, and stack at narrow widths. Description reserves 360 logical pixels. Custom rich-text fields and a schema-provided Steps to Reproduce appear inline. Properties use schema display names in the reference order. Scalar references offer typed, paged search; selected IDs and labels remain separate through saving and transfer. Custom reference types outside the supported catalog remain unavailable. Tags/Milestones load their complete selection on Edit, then offer typed search/add/remove controls; incomplete loads retain the previous state.

The Tasks tab shows ID, Name, State, Estimate, To Do, Actuals and Owner, with wrapped opening links and horizontal scrolling. Add task opens the full task detail editor and carries the parent link, project and current owner into the create request. Its state defaults to Defined only when the schema advertises that value. The remove control confirms permanent deletion; a changed revision or parent blocks it. A failed delete preserves the row and explains the failure. Successful deletion reloads the collection.

Successful saves preserve acknowledged values when a response omits those fields. Explicit returned values still win, and typing performed while saving remains in the editor.


When an item changes on Rally, Reload item retains local edits and unsent comments while updating untouched fields. Fields changed in both places show Keep my edit / Use Rally value and View full comparison. Unresolved choices block saving and survive a transferred or restored tab. Reload also preserves typing made while its request was running.

The Color control uses the [documented WSAPI palette](https://knowledge.broadcom.com/external/article/11610/rally-wsapi-display-colors-of-work-item.html), or values advertised by the workspace schema. Default color clears the attribute. Writable Tags/Milestones use [arrays of reference objects](https://knowledge.broadcom.com/external/article/225337/how-to-use-collections-in-wsapi.html); all selected records must load before editing or saving. Changing totals, missing/repeated records, invalid references and selections over 10,000 items leave the field unavailable with a retryable error. Collection summaries after a save retain the acknowledged selection when their counts match; a different count requires reloading and comparison.

Rally’s filter builder combines Iteration, FY Quarter, Team, Tags and Type clauses with “is”, “is not” and “contains”. Exact reference choices use paged search and preserve IDs separately from labels; Tags use collection membership. All clauses combine with the applied advanced query on the server; the current page endpoint constrains Type. Existing mixed-artifact board work remains separate.
