Fastrock 0.4.0-alpha.3 adds bounded navigation through large conversations and a native Goose provider-defaults form. It includes unmodified Goose 1.57.0 and vwork 0.3.4; neither needs a separate installation. Goose's Bedrock, direct OpenAI and direct Anthropic providers use existing Goose configuration and credentials. Codex connections are removed, while their files remain untouched.

History opens a 100-entry page with Oldest, Earlier, Later and direct position navigation. New activity leaves the reading position fixed; Latest or sending a message returns to the live conversation. Page restoration decodes only the indexed compressed pages required, and full export retains the original conversation.

Settings → Goose → Provider defaults edits the default provider/model, AWS profile/region and supported provider endpoints through Goose's public APIs. Saving preserves existing credentials, extensions and other settings; restart applies the changes. AWS defaults are shared across sessions, and environment overrides still take precedence. Credential editing is unavailable because unchanged Goose exposes no public vault-only writer.

The native Slint interface has the T3-style sidebar and conversation header, a permanent Rally project with independent document tabs, and multiple windows sharing one runtime. Rally's existing workflows and optional temporary AI assistance remain available; proposed writes require human Apply. Vwork browsing, revision-checked editing and compaction use the embedded database owner. Opening a repository registers committed HEAD in process and starts a chat in its own virtual workspace; dirty source files remain untouched. Chats in different workspaces group under one repository. Forks preserve history and tools, isolate child edits, and retain their bindings after restart. Integration requires a reviewed merge guarded by both workspace revisions; conflicts and stale reviews leave the workspaces unchanged.

Search matches titles and current summaries locally, then performs bounded parallel fuzzy matching. Background cheap-model summaries replace a single compressed record per conversation in vwork's redb. Settings identifies the cheap provider/model, defaulting to Bedrock GPT-6 Luna. Large histories use compressed cold pages and bounded render caches.

Closing the last window keeps work running in the tray. Explicit Quit saves and exits. Process or backend recovery restores persistent chats, drafts and queues paused until Resume; uncertain submissions remain review-only and are never blindly replayed.

This is an incomplete 0.4.0 prerelease. Full T3 orchestration/delegation and auxiliary-panel parity, vault-only credential setup, project-local plugin discovery from compressed source, and original window-layout/temporary-session recovery remain in progress. Workspace forks require a bound conversation and explicit defaults for its vwork extensions. Unchanged Goose currently limits independent concurrent AWS credential/region profiles and custom reasoning values. Required Bedrock routes have fixture coverage; live working profiles still require user validation before the final release. See [capabilities and limitations](https://github.com/allquixotic/fastrock/blob/main/docs/goose-acp.md).

On games, the full 1,000-conversation/eight-concurrent-stream/10,000-message workload passed. In one comparison with signed 0.3.4, the alpha.3 implementation candidate opened history in 403 versus 1,103 ms in the earlier baseline; recent-history scroll-frame p95 was higher (10.4 versus 8.5 ms). First/middle/last history jumps took 4–6 ms, and middle-page scroll-frame p95 was 6.1 ms. Fastrock process memory peaked at 218 MB versus 194 MB with Goose external, while total process-tree committed memory was 165 versus 225 MB. All 10,000 messages exported intact. The eight streams were active concurrently and cancelled by benchmark Quit. These are single-run observations; [methodology and evidence](https://github.com/allquixotic/fastrock/blob/main/docs/PORT-VERIFICATION.md) describe the limits.

Application/dependencies use opt-level 2 with no LTO, no debug information, 256 codegen units, incremental compilation and no stripping. CI builds both platforms, runs Windows Rust and local-provider/native UI/recovery fixtures, signs and timestamps the exact Windows executable, and publishes a Windows x64 ZIP with checksums and attestation. macOS is compiled for compatibility only. No tests contact live providers or perform production Rally writes.
