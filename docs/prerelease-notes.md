Fastrock 0.4.0-rc.3 embeds unmodified Goose 1.57.0 and vwork 0.3.4 in one process. Neither needs a separate installation. Core services use in-process Rust APIs; configured extensions, hooks, credential helpers and user/agent tools retain their ability to launch programs. Codex connections are removed, while their conversation files stay untouched.

The native Slint interface follows T3 Code 0.1.5, with repository projects, conversation groups, pinning, snoozing, settling, drag ordering, batch actions, local search and a command palette. Project settings save a default Git reference; new conversations receive isolated compressed workspaces. Native files, Changes, Review, terminals and checkpoints support the coding workflow. Web previews open in the system browser. Quota features and external agent servers are excluded.

Rally remains a permanent virtual project with independent, closable document tabs and boards. Existing editing, filtering, ranking, saved views and other Rally workflows remain available. Optional AI assistance uses an explicit temporary session; applying proposed changes requires human action.

Goose provides Bedrock, direct OpenAI and direct Anthropic models, tools, hooks, recipes and code mode. Existing configuration and credential entries remain in place. Native provider defaults and named direct-provider profiles support OS-vault credentials, independent endpoints and saved reasoning defaults. Goose's public APIs still limit concurrent AWS profile/region isolation and arbitrary reasoning values. Its private hook manager also limits per-conversation hook roots. See [integration details](https://github.com/allquixotic/fastrock/blob/main/docs/goose-acp.md).

Agents can delegate into isolated workspaces, exchange messages, wait and interrupt work. Integrating changes requires explicit review and revision checks. Timed and HMAC-authenticated webhook schedules run in process, with durable delivery identities and occurrence claims. Restart restores conversations, queues, schedules, temporary side chats and their original native windows; work waits for Resume, and uncertain tool calls are never automatically replayed. Closing the last window leaves Fastrock in the tray; explicit Quit stops work and exits.

Search matches titles and current summaries locally, then uses bounded parallel fuzzy matching. Background cheap-model compaction replaces one compressed summary per conversation in vwork's redb; original conversations remain intact. Settings identifies the cheap profile, defaulting to Bedrock GPT-6 Luna. Cold transcript pages use lossless compression with bounded decoded and rendered caches. History supports direct navigation through large conversations, and complete export retains all messages.

This release candidate uses local provider and Rally fixtures for automated acceptance. Required Bedrock Runtime OpenAI and US cross-region Anthropic routes still need validation with the user's working profiles before the final 0.4.0 release. Fixture coverage does not establish AWS model availability or account access. [Verification evidence and benchmark methodology](https://github.com/allquixotic/fastrock/blob/main/docs/PORT-VERIFICATION.md) distinguish automated coverage from live acceptance.

Distribution is a Windows x64 ZIP built, signed, timestamped, verified and attested through CI. macOS is compiled for compatibility only. Application/dependencies use opt-level 2, no LTO or debug information, 256 codegen units, incremental compilation and no stripping. No tests contact live providers or perform production Rally writes.

RC1 stopped before signing because a checkpoint fixture inherited the CI host’s Git line-ending conversion. RC2 makes that fixture deterministic; application behavior and the recorded full-scale benchmark are unchanged. No RC1 binary was published.

RC3 pauses search-summary backfill while any foreground conversation is running, cancels and requeues in-flight summary work, and excludes unfinished tool turns from backfill. Search summaries remain tied to the whole completed user turn. It reuses an existing user-wide vwork policy, removes the managed duplicate installed by RC2, and preserves configuration comments during plugin registration and native settings edits. Previously lost comments are not reconstructed; original hook migration backups remain intact. Timing-only diagnostics separate session setup from the first-response wait. These changes address confirmed contention and migration defects; the reported live three-minute delay still needs a measured comparison with the working profile.
