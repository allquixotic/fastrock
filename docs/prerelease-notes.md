Fastrock 0.4.0-alpha.1 is the first embedded-runtime milestone. It includes unmodified Goose 1.57.0 and vwork 0.3.4; neither needs a separate installation. Goose's Bedrock, direct OpenAI and direct Anthropic providers use existing Goose configuration and credentials. Codex connections are removed, while their files remain untouched.

The native Slint interface has the T3-style sidebar and conversation header, a permanent Rally project with independent document tabs, and multiple windows sharing one runtime. Rally's existing workflows and optional temporary AI assistance remain available; proposed writes require human Apply. Vwork browsing, revision-checked editing and compaction use the embedded database owner.

Search matches titles and current summaries locally, then performs bounded parallel fuzzy matching. Background cheap-model summaries replace a single compressed record per conversation in vwork's redb. Settings identifies the cheap provider/model, defaulting to Bedrock GPT-6 Luna. Large histories use compressed cold pages and bounded render caches.

Closing the last window keeps work running in the tray. Explicit Quit saves and exits. Process or backend recovery restores persistent chats, drafts and queues paused until Resume; uncertain submissions remain review-only and are never blindly replayed.

This is an incomplete 0.4.0 prerelease. Full T3 orchestration and auxiliary-panel parity, repository/workspace binding, graphical provider/credential setup, arbitrary old-history navigation acceptance, and original window-layout/temporary-session recovery remain in progress. Unchanged Goose currently limits independent concurrent AWS credential/region profiles and custom reasoning values. Required Bedrock routes have fixture coverage; live working profiles still require user validation before the final release. See [capabilities and limitations](https://github.com/allquixotic/fastrock/blob/main/docs/goose-acp.md).

On games, the full 1,000-conversation/eight-stream/10,000-message workload passed. In one comparison with signed 0.3.4, opening took 403 versus 1,103 ms; scroll-frame p95 was similar (8.7 versus 8.5 ms). Fastrock process memory peaked at 228 MB versus 194 MB with Goose external, while total process-tree committed memory fell from 225 to 175 MB. These are single-run observations; [methodology and evidence](https://github.com/allquixotic/fastrock/blob/main/docs/PORT-VERIFICATION.md) describe the limits.

Application/dependencies use opt-level 2 with no LTO, no debug information, 256 codegen units, incremental compilation and no stripping. CI builds both platforms, runs Windows Rust and local-provider/native UI/recovery fixtures, signs and timestamps the exact Windows executable, and publishes a Windows x64 ZIP with checksums and attestation. macOS is compiled for compatibility only. No tests contact live providers or perform production Rally writes.
