Fastrock now defaults to installed Goose over ACP. One `goose acp` child supports simultaneous conversations with independent streaming, cancellation and permission prompts. No Goose crates or runtime are compiled into Fastrock; configure and update Goose separately. Goose CLI 1.56.0 or newer is recommended. Use `FASTROCK_GOOSE` to select its executable.

Native session controls are populated from Goose's advertised configuration options. History loads from Goose, while session names, archive, compaction and steering use its extensions. Queued drafts are saved locally. Rally's existing assistant tools are exposed through a scoped loopback MCP bridge; proposed writes still require Apply. Installed Codex remains selectable for existing Codex conversations and Codex-specific features.

See [Goose architecture and capability limits](https://github.com/allquixotic/fastrock/blob/main/docs/goose-acp.md). This is a prerelease: fixtures exercise transport and UI behavior without a live provider account. Codex-specific forks, review, recap and other unsupported RPCs are not emulated.

Fast build settings remain opt-level 0, no debug information, no LTO, 256 codegen units and incremental compilation. CI builds both platforms, executes Rust tests and both backend Rally UI fixtures on Windows, then publishes signed packages. The Windows executable has Authenticode signing and an RFC 3161 timestamp. The Apple Silicon DMG is Developer ID signed, notarized, stapled and verified. No tests or GUI run on the Mac. Packages include SHA-256 checksums and GitHub attestations. No production Rally writes occur in tests.
